# テーブル定義書

## users

### 概要
CircuitStockを利用するユーザーを管理する。

| カラム名 | 論理名 | データ型 | PK | FK | NULL | UNIQUE | DEFAULT | 制約・補足 |
|---|---|---|---|---|---|---|---|---|
| id | ユーザーID | BIGINT | ○ | - | 不可 | - | - | 自動採番 |
| user_name | ユーザー名 | VARCHAR(32) | - | - | 不可 | - | - | 最大32文字、空文字不可、スペースのみ不可 |
| email | メールアドレス | VARCHAR(255) | - | - | 不可 | ○ | - | 最大255文字、メールアドレス形式、大文字・小文字を区別しない  |
| password | パスワード | VARCHAR(255) | - | - | 不可 | - | - | ハッシュ化して保存、入力時15〜64文字 |



## categories

### 概要

部品を分類するためのカテゴリを管理する。

| カラム名 | 論理名 | データ型 | PK | FK | NULL | UNIQUE | DEFAULT | 制約・補足 |
|---|---|---|---|---|---|---|---|---|
| id | カテゴリID | BIGINT | ○ | - | 不可 | - | - | 自動採番 |
| user_id | ユーザーID | BIGINT | - | ○ | 不可 | ※ | - | users.idを参照、ON DELETE CASCADE （ユーザー削除時に連動削除） |
| category_name | カテゴリ名| VARCHAR(32) | - | - | 不可 | ※ | - | 最大32文字、空文字・スペース・改行・タブ不可、大文字小文字、全角半角は同一扱い |

### 制約・補足

- 同一ユーザー内では、同じカテゴリ名を登録不可とする。
- 別ユーザーであれば、同じカテゴリ名を登録可能とする。
- カテゴリ名の登録・変更時は、同じ入力ルールと重複チェックを適用する。
- カテゴリ名は、大文字小文字・全角半角を正規化して保存する。
- カテゴリ名には記号を使用可能とする。
- カテゴリ名が32文字を超える場合は、切り捨てず登録エラーとする。
- 使用中のカテゴリは削除不可とする。
- 使用中のカテゴリを削除する場合は、そのカテゴリを参照している部品を別カテゴリへ変更し、参照0件にしてから削除する。
- 部品はカテゴリ名ではなくカテゴリIDを参照するため、カテゴリ名変更時に部品データ自体の更新は不要とする。
- `user_id`はユーザーが入力せず、ログイン中ユーザーのIDをシステム側で設定する。
- `user_id`は画面上では基本的に表示しない。

### UNIQUE制約

※ `user_id`単体、`category_name`単体にはUNIQUE制約を付けない。

複合UNIQUE制約として、以下の組み合わせで重複を禁止する。

`user_id + category_name`

ただし、カテゴリ名は大文字・小文字、全角・半角を同一扱いとする。

### 実装時の検討事項

Issue #5では、以下を**仕様として確定**する。

- 同一ユーザー内ではカテゴリ名の重複を禁止する。
- 大文字・小文字は同一として扱う。
- 全角・半角は同一として扱う。
- カテゴリ名を正規化して保存する。
- DB側でも重複を保証する。
- 空文字・スペース・改行・タブなどの禁止について、Laravel側のバリデーションに加えてDB側でも制約を設ける。

一方、PostgreSQLで大文字小文字・全角半角を同一扱いにした上で複合UNIQUE制約を実現する具体的な方法は、実装時に決定する。

候補としては、正規化後の値を用いたUNIQUE制約や、`LOWER()`等を利用したインデックス、PostgreSQLの機能・拡張などを検討する。

Laravelでは、`user_id`の外部キー定義に`foreignId()`と`constrained()`を使用し、ユーザー削除時の連動削除を設定する想定とする。
